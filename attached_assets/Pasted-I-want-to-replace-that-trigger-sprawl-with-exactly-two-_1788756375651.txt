Trigger 1 — Exit Intent (always fires)

Detect: mouse-exit toward the top of viewport (desktop) OR back-button/tab- switch equivalent on mobile — reuse whatever exit-intent detection already exists in the codebase, just consolidate it into one trigger instead of several overlapping ones.

Behavior:

If cart has items → show "Continue on WhatsApp" popup with a wa.me link, message pre-filled with the actual cart contents (product names, quantities) pulled from the existing cart API call.
If cart is empty → show "Continue on WhatsApp" popup with a generic pre-filled message like "Hi, I was checking out [store name] and wanted some help finding something."
One popup, one button, no branching UI, no secondary CTA competing with it. Keep SMS (if it currently exists as a co-equal option) as a small text-link fallback under the WhatsApp button, not equal visual weight.
This trigger should fire at most once per session.
Trigger 2 — Engagement (persona popup, not an exit signal)

Fires while the shopper is actively browsing, before any exit intent. Name it "Hi, I'm Rohan" (or pull a configurable persona name/brand placeholder — make this a config value per merchant later, hardcode "Rohan" as default for now).

Fire condition (implement as simple, tunable config constants, not hardcoded magic numbers inline):

ENGAGEMENT_ADD_TO_CART_THRESHOLD = 2 (fires once the shopper has added 2+ items to cart in the current session), OR
ENGAGEMENT_DWELL_THRESHOLD_SECONDS = 45 (fires once the shopper has spent 45+ seconds on a single product or collection page without either trigger already firing)
Whichever condition is met first fires the popup. Only fires once per session. Never fires if Trigger 1 has already fired this session.

Content logic — based only on current page context, no product data lookups beyond what's already available client-side:

If on a product or collection page: read the Shopify product type / collection handle (already exposed client-side via window.ShopifyAnalytics / theme Liquid object / meta tags — use whatever's cheapest to read without new merchant setup) and phrase the popup around that category. Example: "Looking at jeans — want a suggestion, or help with sizing?" with two tappable options: "Suggest something" and "Size help."
If on homepage or a page with no clear single category (browsing broadly): show a 3-option menu, exact wording locked as:
"Suggest something for me"
"Size help"
"Something else"

Selecting any option does NOT trigger any on-site resolution — no size chart display, no product card, no inline content. It only tags the selected intent into the outgoing WhatsApp pre-filled message and then shows the same "Continue on WhatsApp" CTA as Trigger 1, with that context appended. Example pre-fill: "Hi, I was looking at jeans on [store name] and wanted a suggestion" or "...and had a sizing question."
